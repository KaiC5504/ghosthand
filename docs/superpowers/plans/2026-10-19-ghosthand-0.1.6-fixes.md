# ghosthand 0.1.6 Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the four real problems in the 2026-10-18/19 failure log (BiliFast, Flutter 3.47): `set_text` refused by Flutter fields, no scroll action, `keys` rejecting punctuation, and press refusals shown as raw negative hex.

**Architecture:** UIA refusals become a typed `Refused(code)` that `Desktop` turns into plain-language errors. `set_text` falls back to focusing the field and posting `WM_CHAR`s to it in the background, then reads the field back to prove the text landed. A `scroll` / `scroll_up` action uses UIA ScrollPattern on the element or its nearest scrollable ancestor, and says plainly when nothing scrolls (always the case in Flutter). `keys` learns US-layout punctuation.

**Tech Stack:** unchanged: Python 3.14 + uv, `mcp==2.3.0`, `comtypes==1.4.17`, `pillow==12.3.0`, `pytest==9.1.1`.

**Spec:** `docs/superpowers/specs/2026-10-12-ghosthand-design.md`, plus the findings below. They come from the failure log and a live spike on Kazumi on 2026-10-19.

## Findings this plan rests on

- Flutter's Windows accessibility bridge (`flutter_platform_node_delegate.cc`, `AccessibilityPerformAction`) handles only `kDoDefault` (tap), `kFocus` (accessibility focus) and `kScrollToMakeVisible` (showOnScreen). Every other action returns false, so UIA `SetValue` on a Flutter field always fails with `E_FAIL` ("Unspecified error"). Reproduced with ghosthand's own `set_text` on Kazumi's search field.
- Before it has focus, Kazumi's search field exposes no ValuePattern at all (role `edit`, `[default]` only). After a `default` action (tap) it has keyboard focus and a ValuePattern.
- With the field focused and the window in the background, `WM_CHAR`s posted to the window's focused child (`FLUTTERVIEW`) typed `ab 冰菓/x😀` exactly, including the emoji's surrogate pair. Posted `end` plus backspaces cleared it. Extra backspaces on an empty field do nothing.
- Flutter exposes no ScrollPattern and no ScrollItemPattern (all 62 Kazumi elements checked). Its `AXPlatformNodeWin::ScrollIntoView` never sets the action type, so it could not reach showOnScreen even if exposed. UIA `SetFocus` and IAccessible2 do not scroll. A posted `WM_MOUSEWHEEL` does scroll, but Flutter's `OnScroll` uses `GetCursorPos`, so it scrolls whatever is under the user's real cursor. It is rejected.
- Press refusals in the log: `-0x7ffbfe00` = `0x80040200` `UIA_E_ELEMENTNOTENABLED` (disabled), `-0x7feceaf7` = `0x80131509` `UIA_E_INVALIDOPERATION`.

## Global Constraints

- Never move the mouse and never post mouse messages (`WM_MOUSEWHEEL`, `WM_MOUSEMOVE`, clicks). Typing uses posted keyboard messages only, as `keys` already does.
- Dependencies are unchanged; no `uv.lock` change.
- Tool output and error text speak to Claude and call the person at the PC "the user"; every error names the problem and the next step.
- Never put a field's text into an error when the field is a password field (errors are written to the failure log).
- Comments only for the non-obvious why; match the file's density.
- All UIA calls stay on the `_uia_thread`; `win32.py` and `keys.py` stay free of comtypes.
- Ship as plugin version `0.1.6`.

## Review Focus

1. **The field did not really get focus, so posted characters would land in another control.** ghosthand must type nothing and say so. Pinned in Task 3 (`test_set_text_types_nothing_when_the_field_will_not_take_focus`).
2. **A password field whose typing went wrong.** The error must not contain the typed text or what the field holds. Pinned in Task 3 (`test_set_text_never_echoes_a_password_back`).
3. **A multi-line field, or one the clearing missed** (`end` reaches only the end of the caret's line). The result must be an error quoting what the field now holds, never "done". Pinned in Task 3 (`test_set_text_reports_what_the_field_holds_when_typing_went_wrong`).
4. **Emoji and other characters outside the BMP.** Each must be sent as its two UTF-16 units. Pinned in Task 2 (`test_text_is_sent_as_utf16_units`).
5. **A scroll on a list already at its end.** The error must say it cannot scroll further, not show a raw code. Pinned in Task 1 (`test_refusal_codes_are_explained`).

- [ ] **Step 3: Implement**

`refusal` maps the codes below. Every message ends with a next step.

| code | meaning | message starts |
|---|---|---|
| `0x80040200` | element not enabled | `{ref} is disabled right now, so {action} did nothing. Read the window to see what it waits for (a required field, loading).` |
| `0x80040201` | element not available | `stale: {ref} went away during {action}. Read the window again.` |
| `0x80131509` | invalid operation | for `scroll`/`scroll_up`: `{ref} cannot scroll further that way.`; otherwise `the app says {action} is not possible on {ref} in its current state. Read the window again.` |
| `0x80131505` | timeout | `the app did not answer {action} within 2 s; it may be busy. Wait, then read the window again.` |
| anything else | | `{action} failed: the app refused it ({text}, 0x{code:08X}). Read the window again.` (omit `text, ` when empty) |

In `uia.py`, catch `comtypes.COMError` and raise `Refused(error.hresult & 0xFFFFFFFF, error.text or "")`. `Desktop.act` calls `backend.perform` inside its `_guarded` work and turns `Refused` into `GhostError(refusal(...))`, so the close-mid-call rule still applies. `set_value`'s `Refused` is handled in Task 3; until then `Desktop.set_text` turns it into `GhostError(refusal(error.code, "set_text", ref, error.text))`.

### Task 3: set_text types into fields that refuse direct text

**Files:**
- Modify: `desktop/src/ghosthand/model.py`, `desktop/src/ghosthand/uia.py`, `desktop/src/ghosthand/win32.py`, `desktop/src/ghosthand/desktop.py:80-90`
- Modify: `desktop/tests/fakes.py`
- Test: `desktop/tests/test_desktop.py`, `desktop/tests/test_acceptance_real.py`

**Interfaces:**
- Consumes: `Refused`, `refusal` (Task 1); `utf16_units`, `parse_keys` (Task 2).
- Produces: `model.FieldState`, a frozen dataclass with `focused: bool`, `value: str | None` and `password: bool = False`.
- Produces: `Backend.field_state(element) -> FieldState` and `Backend.focus(element) -> None`.
  - `UiaBackend.field_state` reads current (not cached) `HasKeyboardFocus` and `IsPassword`.
  - It reads the value from the ValuePattern when one is available now, otherwise from LegacyIAccessible's value. The value is `None` when neither answers.
  - `UiaBackend.focus` calls `SetFocus()` and turns `COMError` into `Refused`.
- Produces: `Win32.post_text(hwnd: int, text: str) -> None` posts `WM_CHAR` (0x0102) for each of `utf16_units(text)` to `_focused_child(hwnd)`, with lParam 1.
- Produces: fakes.
  - `FakeElement(..., refuses_text: int | None = None, focusable: bool = False, password: bool = False)` with attribute `focused = False`.
  - `FakeBackend.set_value` raises `Refused(refuses_text)` when set; `FakeBackend.focus` sets `focused = focusable`; `FakeBackend.field_state` reports `focused`, `data.value` and `password`.
  - `FakeWin.post_text` appends `(hwnd, text)` to `self.texts` and calls `self.on_text(text)` if set; `FakeWin.post_keys` also calls `self.on_keys(strokes)` if set.

**Behaviour of `Desktop.set_text(ref, text, submit)`, all inside `_guarded`:**
1. `backend.set_value`. If it returns True, the headline is `text set on {ref}`, as today.
2. If it raised `Refused`, or returned False on a node whose role is `edit`, type instead. Any other role keeps today's "takes no direct text" error.
3. If `field_state` says the field is not focused: perform `default` if the node has it, else `press` if it has that (Flutter's tap is what really focuses a field), else `backend.focus`. Then sleep `SETTLE` and check again. Still not focused: raise `{ref} would not take keyboard focus without the mouse, so ghosthand typed nothing. Take a screenshot and tell the user.`
4. If the field holds text: `post_keys(hwnd, parse_keys("end") + [backspace] * len(value))`.
5. `post_text(hwnd, text)`.
6. Check `field_state` up to `round(SETTLE_LIMIT / SETTLE)` times (10), sleeping `SETTLE` between checks, until the value equals `text`; for a password field, until the lengths match. Count the tries rather than reading the clock: the unit tests' `sleep` does not wait, so a clock deadline would busy-loop for 1.5 s.
   - Mismatch: raise `typed into {ref}, but it now holds "{value}" instead. Read the window and fix it, or tell the user.`
   - For a password field, raise `typed into {ref}, but the password field did not end up with the text` instead.
   - Value `None`: accept, and add `could not read the field back to check` to the headline.
7. Headline: `text typed into {ref} (the app refused direct text)`. `submit` then posts `enter` as today.
